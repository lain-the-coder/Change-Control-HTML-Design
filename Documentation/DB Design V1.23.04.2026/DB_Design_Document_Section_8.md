# SECTION 8 — Stored Procedures

This section defines the 3 stored procedures in the system. The scope is intentionally narrow — all business logic lives in the C# service layer (Option C hybrid architecture). These procedures handle only operations that benefit from being atomic database-level actions.

**Stored procedure inventory:**

| # | Procedure | Purpose | Called By |
|---|-----------|---------|-----------|
| 1 | `usp_InsertAuditLog` | Atomic audit log write | .NET AuditService |
| 2 | `usp_CheckActiveRecordsForUser` | Active record check for role change restriction | .NET UserService |
| 3 | `usp_GenerateCCID` | Concurrency-safe sequential CC-ID generation | .NET ChangeControlService |

**What is NOT a stored procedure:**

State transition logic, mandatory field validation, date validation, role-based permission checks, approval status label updates, email notification triggers, and file upload handling are all implemented in the C# service layer. See Section 1.1 for the full architecture rationale.

## 8.1 usp_InsertAuditLog

**Purpose:** Inserts a single audit log entry into the AuditLogs table. Called by the .NET AuditService after each auditable action. Designed as an atomic, single-responsibility operation — receives all values as parameters and performs a straightforward INSERT.

**Why a stored procedure instead of direct EF Core INSERT:**

- Audit logging must succeed independently of the main transaction. If the main business operation succeeds but audit logging fails, the system is in an inconsistent state. The SP provides a clean separation point — the AuditService can call this SP in its own try/catch with appropriate error handling.
- The SP is a single atomic operation with no branching logic — it's a clean fit for a stored procedure.
- Centralises the INSERT statement — if the AuditLogs schema changes (e.g., a column is added), only the SP is updated, not every C# call site.

### Signature

```sql
CREATE PROCEDURE usp_InsertAuditLog
    @EntityType         NVARCHAR(50),
    @EntityId           NVARCHAR(50),
    @ActionType         NVARCHAR(50),
    @ActionDescription  NVARCHAR(500),
    @FieldName          NVARCHAR(100)   = NULL,
    @OldValue           NVARCHAR(MAX)   = NULL,
    @NewValue           NVARCHAR(MAX)   = NULL,
    @PerformedById      INT,
    @PerformedByName    NVARCHAR(200),
    @Timestamp          DATETIME2(7)    = NULL
AS
BEGIN
    SET NOCOUNT ON;

    INSERT INTO AuditLogs (
        EntityType,
        EntityId,
        ActionType,
        ActionDescription,
        FieldName,
        OldValue,
        NewValue,
        PerformedById,
        PerformedByName,
        Timestamp
    )
    VALUES (
        @EntityType,
        @EntityId,
        @ActionType,
        @ActionDescription,
        @FieldName,
        @OldValue,
        @NewValue,
        @PerformedById,
        @PerformedByName,
        ISNULL(@Timestamp, SYSUTCDATETIME())
    );
END;
```

### Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| `@EntityType` | NVARCHAR(50) | Yes | — | 'ChangeControl' or 'User'. Validated by CK_AuditLogs_EntityType. |
| `@EntityId` | NVARCHAR(50) | Yes | — | Business identifier: 'CC-001' for CCs, or a user identifier for user actions. |
| `@ActionType` | NVARCHAR(50) | Yes | — | One of 7 valid values. Validated by CK_AuditLogs_ActionType. |
| `@ActionDescription` | NVARCHAR(500) | Yes | — | Human-readable summary generated by the C# AuditService (e.g., "State changed from Initiated to Pending Implementation Approval"). |
| `@FieldName` | NVARCHAR(100) | No | NULL | The field that changed. NULL for non-field actions (Created, StateChanged). Populated for FieldUpdated actions (e.g., 'Decision', 'Risk Level'). |
| `@OldValue` | NVARCHAR(MAX) | No | NULL | Previous value before the change. NULL for creation events or first-time field population. |
| `@NewValue` | NVARCHAR(MAX) | No | NULL | New value after the change. |
| `@PerformedById` | INT | Yes | — | Users.Id of the person who performed the action. |
| `@PerformedByName` | NVARCHAR(200) | Yes | — | Display name snapshot at the time of the action (denormalized — see Section 3.4). |
| `@Timestamp` | DATETIME2(7) | No | SYSUTCDATETIME() | When the action occurred. Optional — defaults to current UTC time. The C# AuditService passes this explicitly when generating multiple entries for the same action (e.g., 3 field updates + 1 state transition from an approval) to ensure they share the exact same timestamp (BR-8.7.5). |

### Usage Examples (C# AuditService)

```csharp
// Example 1: CC Created
await _auditService.LogAsync(new AuditEntry
{
    EntityType = "ChangeControl",
    EntityId = "CC-001",
    ActionType = "Created",
    ActionDescription = "Change Control CC-001 created",
    PerformedById = currentUser.Id,
    PerformedByName = currentUser.FullName
});

// Example 2: Approval with multiple entries sharing the same timestamp
var timestamp = DateTime.UtcNow;

await _auditService.LogAsync(new AuditEntry
{
    EntityType = "ChangeControl",
    EntityId = "CC-001",
    ActionType = "FieldUpdated",
    ActionDescription = "Decision set to Approve",
    FieldName = "Decision",
    OldValue = null,       // first-time population
    NewValue = "Approve",
    PerformedById = currentUser.Id,
    PerformedByName = currentUser.FullName,
    Timestamp = timestamp  // shared across all entries in this batch
});

// ... repeat for RiskLevel, DecisionComments, StateChanged
// all with the same timestamp value
```

### Error Handling

The SP itself does not include TRY/CATCH — error handling is the responsibility of the calling C# AuditService. If the INSERT fails (e.g., CHECK constraint violation from an invalid ActionType), the SQL Server error propagates to the C# layer where it is caught, logged via Serilog, and handled appropriately.

The SP uses `SET NOCOUNT ON` to suppress the "rows affected" message, reducing network traffic for a frequently called procedure.

## 8.2 usp_CheckActiveRecordsForUser

**Purpose:** Checks whether a user has any active Change Control records. Returns a list of active CC-IDs where the user is either the Change Owner or the Assigned Approver. Called by the .NET UserService before processing a role change request (BR-8.4.11).

**Why a stored procedure:**

- This query spans the ChangeControls table with two OR conditions (owner or approver). Expressing this as a single, optimised SP with a clear contract is cleaner than embedding the query in EF Core LINQ.
- The two composite indexes (`IX_ChangeControls_ChangeOwnerId_CurrentState` and `IX_ChangeControls_AssignedApproverId_CurrentState`) are designed specifically for this procedure.
- The SP returns a result set that the C# service can inspect — if any rows are returned, the role change is blocked and the CC-IDs are included in the error message.

### Signature

```sql
CREATE PROCEDURE usp_CheckActiveRecordsForUser
    @UserId INT
AS
BEGIN
    SET NOCOUNT ON;

    -- Return all active CC-IDs where the user is the owner or assigned approver.
    -- "Active" = any state other than Closed or Cancelled (BR-8.4.11).
    -- The C# service checks: if any rows are returned, block the role change.

    SELECT DISTINCT cc.CcId, cc.CurrentState,
        CASE
            WHEN cc.ChangeOwnerId = @UserId AND cc.AssignedApproverId = @UserId
                THEN 'Owner and Approver'
            WHEN cc.ChangeOwnerId = @UserId
                THEN 'Owner'
            WHEN cc.AssignedApproverId = @UserId
                THEN 'Approver'
        END AS Association
    FROM ChangeControls cc
    WHERE cc.CurrentState NOT IN ('Closed', 'Cancelled')
      AND (cc.ChangeOwnerId = @UserId OR cc.AssignedApproverId = @UserId)
    ORDER BY cc.CcId;
END;
```

### Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `@UserId` | INT | Yes | The Users.Id of the user whose role is being changed. |

### Return Value

Returns a result set with zero or more rows:

| Column | Type | Description |
|--------|------|-------------|
| `CcId` | VARCHAR(10) | The CC-ID of the active record (e.g., 'CC-001') |
| `CurrentState` | NVARCHAR(50) | The current state of the record (e.g., 'Initiated', 'In Implementation') |
| `Association` | NVARCHAR(20) | How the user is associated: 'Owner', 'Approver', or 'Owner and Approver' |

**If zero rows returned:** The user has no active records — the role change can proceed.

**If one or more rows returned:** The user has active records — the role change must be blocked. The C# service uses the returned CC-IDs to construct the error message: "Cannot change role: User is associated with active records CC-001, CC-003. These records must be Closed or Cancelled before the role change can proceed." (FR-6.2.29).

### Usage Example (C# UserService)

```csharp
public async Task ChangeUserRoleAsync(int userId, string newRole, int adminId)
{
    // Step 1: Check for active records
    var activeRecords = await _dbContext.Database
        .SqlQueryRaw<ActiveRecordDto>(
            "EXEC usp_CheckActiveRecordsForUser @UserId = {0}", userId)
        .ToListAsync();

    if (activeRecords.Any())
    {
        var ccIds = string.Join(", ", activeRecords.Select(r => r.CcId));
        throw new BusinessRuleException(
            $"Cannot change role: User is associated with active records {ccIds}. " +
            "These records must be Closed or Cancelled before the role change can proceed.");
    }

    // Step 2: Proceed with role change
    var user = await _dbContext.Users.FindAsync(userId);
    var oldRole = user.Role;
    user.Role = newRole;
    user.UpdatedOn = DateTime.UtcNow;
    await _dbContext.SaveChangesAsync();

    // Step 3: Audit log the role change
    await _auditService.LogAsync(new AuditEntry
    {
        EntityType = "User",
        EntityId = $"User-{userId}",
        ActionType = "UserRoleChanged",
        ActionDescription = $"User {user.FullName} role changed",
        FieldName = "Role",
        OldValue = oldRole,
        NewValue = newRole,
        PerformedById = adminId,
        PerformedByName = adminFullName
    });
}
```

### Query Performance

The query uses a UNION-style access pattern (OR condition) across two indexed columns. SQL Server's query optimiser can use:

- `IX_ChangeControls_ChangeOwnerId_CurrentState` for the `ChangeOwnerId = @UserId` portion
- `IX_ChangeControls_AssignedApproverId_CurrentState` for the `AssignedApproverId = @UserId` portion

The `DISTINCT` handles the edge case where a user is both the owner AND the assigned approver on the same record (which shouldn't happen per segregation of duties, but the query is defensive).

### Edge Case: Owner and Approver on Same Record

The `Association` column in the result set handles the theoretical scenario where a user appears as both owner and approver on the same CC. While the business rules (BR-8.3.1) prevent this through the single-role model and the role change restriction itself, the SP is defensive — it won't produce duplicate CC-IDs in the result even if the data contains this anomaly.

## 8.3 usp_GenerateCCID

**Purpose:** Generates the next sequential CC-ID in the format CC-XXX (e.g., CC-001, CC-002, ..., CC-999, CC-1000). Designed for concurrency safety — if two CC records are created simultaneously, each gets a unique, sequential ID without gaps or duplicates.

**Why a stored procedure:**

- CC-ID generation requires reading the current maximum value and incrementing it — a classic read-then-write race condition. The SP uses a transaction with appropriate locking to ensure concurrency safety.
- The CC-XXX format requires string formatting that is straightforward in T-SQL.
- Centralising ID generation in a SP ensures every CC record gets its ID from the same source, regardless of which service or code path creates the record.

### Signature

```sql
CREATE PROCEDURE usp_GenerateCCID
    @NewCcId VARCHAR(10) OUTPUT
AS
BEGIN
    SET NOCOUNT ON;

    DECLARE @NextNumber INT;

    -- Use SERIALIZABLE isolation + UPDLOCK to prevent race conditions.
    -- SERIALIZABLE prevents phantom reads (another transaction inserting
    -- between our SELECT MAX and INSERT).
    -- UPDLOCK prevents two transactions from reading the same MAX simultaneously.

    BEGIN TRANSACTION;

        SELECT @NextNumber = ISNULL(MAX(
            TRY_CAST(SUBSTRING(CcId, 4, LEN(CcId) - 3) AS INT)
        ), 0) + 1
        FROM ChangeControls WITH (UPDLOCK, SERIALIZABLE);

        -- Format: CC-XXX with zero-padding to 3 digits minimum.
        -- CC-001 through CC-999, then CC-1000, CC-1001, etc.
        SET @NewCcId = 'CC-' + RIGHT('000' + CAST(@NextNumber AS VARCHAR(7)), 
                                      CASE WHEN @NextNumber > 999 THEN LEN(CAST(@NextNumber AS VARCHAR(7)))
                                           ELSE 3
                                      END);

    COMMIT TRANSACTION;
END;
```

### Parameters

| Parameter | Type | Direction | Description |
|-----------|------|-----------|-------------|
| `@NewCcId` | VARCHAR(10) | OUTPUT | The generated CC-ID (e.g., 'CC-001'). Returned to the calling C# service for insertion into the ChangeControls record. |

### CC-ID Format Rules

| Rule | Detail | BRD Reference |
|------|--------|---------------|
| Prefix | Always 'CC-' | BRD Field 1 |
| Numeric portion | Sequential integer, zero-padded to minimum 3 digits | CC-001, CC-002, ..., CC-999 |
| Beyond 999 | Digits expand naturally | CC-1000, CC-1001, ... |
| Uniqueness | Guaranteed unique via SERIALIZABLE transaction + UNIQUE constraint on CcId | BRD Field 1 |
| Gaps | Allowed but not intentional — no requirement to fill gaps from rolled-back transactions | BRD Field 1 ("no gaps required but no duplicates permitted") |
| Immutability | CC-ID never changes after creation | BRD Field 1 |

### Concurrency Safety

The SP uses two SQL Server locking hints to prevent race conditions:

**UPDLOCK** — Acquires update locks on the rows read by the SELECT. This prevents two concurrent transactions from reading the same MAX value simultaneously. Without UPDLOCK, two transactions could both read MAX = 5, both compute 6, and both attempt to insert CC-006 — the UNIQUE constraint would reject one, but the experience is poor (the rejected transaction gets an error instead of the next valid ID).

**SERIALIZABLE** — The highest isolation level. Prevents phantom reads — another transaction cannot insert a new row between our SELECT MAX and the point where our calling code inserts the new CC record. Together with UPDLOCK, this ensures strict sequential ordering.

**Transaction scope:** The SP only generates the ID — it does not insert the ChangeControls record. The calling C# service receives the ID via the OUTPUT parameter and includes it in the EF Core INSERT. The lock is held briefly (only for the SELECT MAX computation), minimising contention.

### Usage Example (C# ChangeControlService)

```csharp
public async Task<ChangeControl> CreateChangeControlAsync(int creatorUserId)
{
    // Step 1: Generate CC-ID via stored procedure
    var ccIdParam = new SqlParameter
    {
        ParameterName = "@NewCcId",
        SqlDbType = SqlDbType.VarChar,
        Size = 10,
        Direction = ParameterDirection.Output
    };

    await _dbContext.Database.ExecuteSqlRawAsync(
        "EXEC usp_GenerateCCID @NewCcId OUTPUT", ccIdParam);

    string newCcId = (string)ccIdParam.Value;

    // Step 2: Create the CC record
    var cc = new ChangeControl
    {
        CcId = newCcId,
        CurrentState = "Initiated",
        ChangeOwnerId = creatorUserId,
        LastUpdatedById = creatorUserId,
        ImplementationApprovalStatus = "Not Submitted",
        FinalApprovalStatus = "Not Submitted"
        // All other fields NULL (draft state)
    };

    _dbContext.ChangeControls.Add(cc);
    await _dbContext.SaveChangesAsync();

    // Step 3: Audit log the creation
    await _auditService.LogAsync(new AuditEntry
    {
        EntityType = "ChangeControl",
        EntityId = newCcId,
        ActionType = "Created",
        ActionDescription = $"Change Control {newCcId} created",
        PerformedById = creatorUserId,
        PerformedByName = creatorFullName
    });

    return cc;
}
```

### Alternative Considered: SEQUENCE Object

SQL Server 2022 supports `CREATE SEQUENCE` which provides built-in concurrency-safe sequential numbering. We could use:

```sql
CREATE SEQUENCE CcIdSequence AS INT START WITH 1 INCREMENT BY 1;
-- Then: SELECT NEXT VALUE FOR CcIdSequence;
```

This was considered but not chosen because:

- The CC-ID format requires string formatting (CC-XXX with zero-padding) which SEQUENCE doesn't handle — we'd still need a function or inline formatting.
- The SP approach is explicit and self-documented — the ID generation logic is visible in one place.
- If the format needs to change (e.g., adding a year prefix like CC-2026-001), the SP is the only thing modified.
- Either approach works correctly. The SP was selected for clarity and flexibility.
